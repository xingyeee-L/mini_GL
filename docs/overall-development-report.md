# mini_GL 总体开发报告

**报告日期：** 2026-09-10  
**当前版本：** 阶段 0–8 与产品前端 V1 完成；阶段 9 第一纵向切片进行中
**项目性质：** 本地优先、权限感知、来源可追溯的个人知识检索与问答原型

## 1. 执行摘要

mini_GL 已从安全规格和工程骨架发展为一套能够实际运行的本地知识系统。用户可以注册明确授权的 TXT/Markdown 目录，安全同步文件，建立关键词与本地 BGE 向量索引，使用混合检索查找资料，并通过本地 Qwen 模型生成带来源的回答。系统也提供版本化中立聊天 JSON 导入、SQLite 备份恢复、压力与稳定性验证，以及受控只读 Agent 权限层。

本轮完成了产品前端 V1。此前的“验收台”已经被收进系统控制台；新的默认入口面向普通用户，提供首页、搜索、智能问答、知识库与控制台五个清晰工作区。前端保持零第三方运行时依赖，不使用云端字体、CDN、遥测或分析服务。

当前成果适合继续进行本地个人使用、产品演示和合成数据验证，但还不能宣称为面向真实聊天数据或多人企业环境的正式产品。

## 2. 当前产品能力

### 2.1 用户可直接使用的能力

- 从一个统一首页进入搜索、AI 问答和知识库。
- 注册用户明确授权的本地 TXT/Markdown 根目录。
- 安全识别新增、修改、未变化、删除和改名文件。
- 使用 BM25 关键词检索精确查找中文资料。
- 使用 BGE-small-zh-v1.5 进行本地语义向量检索。
- 融合关键词、向量与本地重排结果。
- 使用 Ollama 中的 Qwen3 4B 回答知识库问题。
- 查看每个回答事实的引用和原始来源快照。
- 在资料不足时停止生成并明确拒答。
- 导入版本化中立聊天 JSON；支持合成 QQ/微信格式转换。
- 暂停和恢复数据源，重建索引，删除应用派生数据。
- 备份和恢复 SQLite 数据库，以及撤销数据源注册。
- 查看本地模型、隐私边界、Agent 安全与验收状态。

### 2.2 当前运行架构

```text
用户浏览器
  → 回环 HTTP 服务（127.0.0.1）
    → 权限与路径策略
      → 文件/中立聊天连接器
        → 解析与 SourceDocument 标准化
          → SQLite 原子状态与派生数据
            → BM25 + BGE + 本地重排
              → 上下文构建与证据门控
                → 本地 Qwen
                  → 回答 + 独立 Citation
```

核心运行时保持 Python 标准库优先；机器学习依赖仅用于离线 Embedding。本地模型适配器只接受回环地址，不进行云端自动回退。

## 4. 各阶段关键产出

### 阶段 0：把安全边界写进工程

项目从一开始就规定：不读取真实聊天数据库、不修改原始文件、不静默调用云端模型、不允许检索内容改变系统权限。连接器、解析、标准化、索引、检索、生成和存储被拆成独立模块，为后续替换模型和增加数据源留下边界。

### 阶段 1：第一条端到端数据链路

系统可以注册规范化根目录，拒绝符号链接、Windows 重解析点、目录穿越、超限文件和超深路径。文件以只读二进制方式打开，读取前后核对身份、大小与时间戳；任何扫描错误使整轮同步回滚，避免把“无法访问”误判为删除。SQLite 保存来源、同步游标、文件快照、文档和幂等事件。

### 阶段 2：不依赖 LLM 的检索基线

实现中文关键词索引和检索，保留稳定文档/片段 ID、来源位置、类型、更新时间与延迟。冻结基准为 15 篇合成文档和 25 个问题，BM25 Recall@5/10 为 0.66/0.66，MRR 为 0.56，禁止结果率为 0。

### 阶段 3：本地语义与混合检索

完成 BGE-small-zh-v1.5 与 multilingual-e5-small 的离线比较。30 篇/60 问冻结基准中，BGE 混合检索 Recall@5/10 为 0.9417/0.9917，MRR 为 0.7994，禁止结果率为 0。BGE 在当前笔记本的速度和内存之间更平衡，因此成为默认模型；E5 保留为高质量候选。

### 阶段 4：有来源的本地回答

通过 Ollama 接入 `qwen3:4b-instruct-2507-q4_K_M`。系统先执行权限过滤与混合检索，再进行上下文去重和 Token 预算；无证据时不调用模型。Citation 由授权数据库生成，而不是相信模型自己声称的来源。8 个合成 RAG 场景全部通过，热运行 P50 约 319 ms、P95 约 895 ms。

### 阶段 5：聊天数据的安全中间层

核心系统只认识版本化中立 JSON，不依赖某个 QQ/微信客户端版本。导入要求用户确认自己有权使用文件，拒绝非法编码、超限、链接和读取期间变化。当前 QQ/微信适配仅针对虚构合成格式，不读取、不解密客户端数据库。

### 阶段 6：可理解和可控制的本地界面

完成数据源注册、同步、索引、搜索、问答、来源展开、暂停恢复和派生数据删除。HTTP 服务只允许绑定 `127.0.0.1` 或 `localhost`，API 使用进程级请求令牌抵御恶意网页调用。所有动态正文使用纯文本 DOM 渲染，避免把资料当成 HTML 执行。

### 阶段 7：从演示原型走向长期运行

使用 SQLite 一致性备份 API 创建校验后的快照；恢复只写入全新目标，拒绝覆盖和损坏文件。完成 1,000 个 4 KiB 文件、单个 10 MiB 文件以及 50 轮×100 文件稳定运行测试，来源哈希保持不变，SQLite 完整性为 `ok`。本地模型异常被转换为不泄露正文和端点细节的恢复提示。

### 阶段 8：受控而非泛化的 Agent

Action Policy 取 User、Agent、Tool、Policy 四方权限交集，服务端签发可验证决定。搜索、回答和来源预览已进入只读执行门，并记录不包含正文的审计元数据。独立安全评审后修复了调用方自报确认、伪造决定、审计覆盖、精确过期和中断恢复问题。删除、撤销、任意 Shell、任意路径和任意网络没有进入 Agent 能力面。

前端 V1 使用语义 HTML、CSS 和原生 JavaScript，拆分为独立静态资源，由现有 Python 回环服务提供。这样没有新增 npm、Node 或浏览器运行时依赖，适合当前本地原型阶段，也避免为了界面过早扩大供应链和构建复杂度。

- 使用证据不足的数据源提问时，系统明确拒答。
- 切换到阶段 4 合成数据源后，问题“系统如何保护原始文件？”成功生成带 5 个引用的回答并通过证据检查。

## 6. 安全与隐私现状

### 已落实

- 原文件连接器只读；派生数据与原始资料分离。
- 路径规范化、根目录边界、扩展名、大小、深度和链接防护。
- 完整扫描成功后才提交删除事件。
- 本地模型只允许回环 HTTP，无代理、重定向和云端回退。
- 检索范围在生成之前确定，检索正文不能授权工具。
- 回答有来源或拒答；来源预览只允许当前授权快照。
- 本地 API 有 CSRF 防护和严格 CSP。
- 无应用遥测、分析、崩溃上报或后台上传。
- 测试和 Git 只使用虚构合成资料。

### 尚不能承诺

- 尚未针对真实 QQ/微信导出器完成专项格式与隐私审查。
- 尚未进行第三方专业渗透测试或正式安全认证。
- 当前是本机单用户所有者模型，不是企业级多租户权限系统。
- 备份文件的外部加密、密钥管理和安全擦除仍由操作系统/用户负责。

## 9. 后续展望与建议路线

### 路线 A：把 mini_GL 做成真正可日用的本地产品

下一里程碑建议定义为“阶段 9：桌面化与真实数据准入”。重点不是增加更多 Agent 动作，而是让现有能力容易安装、容易更新、容易备份，并以严格门禁完成第一个真实导出格式。成功标准应包括一键启动、本地模型诊断、跨数据源搜索、可视备份恢复和完整卸载清理。

### 路线 B：提升知识理解，而不是只扩大模型

可以逐步加入文档层级、标题路径、时间线、实体与关系、会话主题等结构化信号，使检索理解“人、项目、决策和事件”的关系。这比单纯换更大 LLM 更接近 Glean 类产品的核心壁垒。

### 路线 C：Agent 保持渐进开放

先考虑可验证、可撤销、应用自有范围内的动作，例如“保存本地收藏”“生成待办草稿”“创建派生摘要”。每增加一个动作，都要有固定参数、幂等键、预演、人类确认、失败补偿和独立测试。对原始资料的写入不应成为近期目标。

### 路线 D：从单机权限模型走向多主体权限

如果未来面向团队，需要重新设计身份、用户/组、连接器 ACL 同步、结果过滤、审计保留和管理员策略。当前 owner-only 设计不能直接扩展为企业权限系统，应该作为新的架构阶段，而不是小改动。

## 10. 建议的下一阶段验收标准

阶段 9 可以采用以下完成定义：

- 用户无需命令行即可安装、启动、停止和检查本地模型。
- 搜索可安全覆盖多个选定数据源并解释每条结果的权限来源。
- 会话历史只保存在本机，可单独删除，删除不影响原始资料。
- 备份、恢复、撤销和派生数据删除都有可视确认与结果回执。
- 第一个真实导出器只在最小脱敏样本专项审查通过后开放。
- 升级、失败恢复和卸载后不存在不可解释的残留数据。
- 自动测试、真实浏览器关键路径、隐私审查和恢复演练全部通过。

## 11. 总结

mini_GL 已经完成了一个重要闭环：从用户授权的数据，到安全接入、混合检索、本地生成、来源核验、恢复能力和受控 Agent，再到面向普通用户的产品前端。项目目前最大的优势不是模型规模，而是清晰、可测试的安全边界和完整端到端链路。

下一步最有价值的工作，是把这套能力变得可安装、可长期使用，并在严格审查下接入第一个真实数据格式；不是过早扩大写操作或追求不可控的通用 Agent。

## 12. 阶段 9 最新进展

阶段 9 已完成前两条纵向切片：增加双击/命令行一键启动、本地运行诊断、跨全部已授权数据源搜索与 RAG、网页端备份恢复、Windows 原生文件夹选择器，以及真实目录显式授权门禁。文件夹选择动作只把路径带回表单，不注册、不扫描正文；跨数据源检索和回答会逐个来源重新执行权限校验和只读审计，引用会携带真实来源身份。模型中心会检查 Ollama、固定 Qwen 和本地 BGE，并显示下一步恢复建议。服务端拒绝同一端口的第二个实例，避免残留进程导致前后端版本错配。系统不会猜测或自动扫描个人文件夹。

尚未完成可执行安装的首次启动模型向导、安装包、升级/卸载和真实聊天导出器审查，因此阶段 9 仍为进行中。
