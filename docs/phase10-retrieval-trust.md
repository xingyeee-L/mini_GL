# 阶段 10：检索可信度与可核验引用

## 目标

让检索结果和本地模型回答不仅“看起来合理”，还能够定位、核验和纠错。阶段 10
继续遵守本地优先、来源只读、数据源隔离和无云端回退的边界。

## 已完成

- Markdown 按标题层级和段落进行结构化分块，并保存章节路径。
- 每个分块保存正文中的精确起止字符位置；回答引用展示文件、章节与字符范围。
- 混合检索增加实体感知重排，对课程编号、英文技术词和标题精确命中加权。
- 回答校验从整段词面重叠升级为逐段、逐实体检查，能识别“课程名称正确但语言属性错误”等张冠李戴。
- 用户可将单条引用标记为“正确”或“错误”；反馈仅保存在本机 SQLite，且不保存额外正文。
- 增加 10 条课程检索固定基准，要求 Top-1 命中率为 100%。
- 数据库升级到 schema 13。旧版分块没有可信位置，因此升级时清空派生索引，原始文件和标准化文档不受影响；用户需重新建立关键词和向量索引。

## 验收标准

- 阶段 10 合成基准 10/10 Top-1 命中。
- 原有中文检索、混合检索、回答校验、网页接口和数据库测试全部通过。
- 引用反馈必须验证会话、数据源、文档和分块之间的真实关系，不能跨来源伪造。
- 所有测试只读取仓库内合成资料，不读取真实个人文件或 `data/`。

## 当前限制

- 实体感知重排器仍是可解释的本地规则模型，不是训练得到的 cross-encoder。
- Markdown 可以提供标题层级；其他格式当前主要提供精确字符范围，尚未统一页码、工作表、幻灯片等原生结构坐标。
- 技术属性冲突检查目前覆盖常见编程语言，后续应扩展为通用实体—属性一致性模型。
- 引用反馈已形成可靠的本地数据闭环，但尚未自动训练或调整排序权重，避免少量反馈直接污染检索行为。

## 下一步

优先用真实但已脱敏的失败案例扩充离线基准，再实现 PDF 页码、XLSX 工作表、PPTX
页号与 DOCX 标题层级的统一定位。之后再评估小型本地 cross-encoder，并以固定基准和延迟预算决定是否替换规则重排器。
