# 阶段 11：桌面产品化收口

## 定义

阶段 11 把开发仓库形态的 mini_GL 收口为可重复安装、可一键启动、可自检、可备份、
可审查卸载的 Windows 本地产品。它不自动下载模型、不增加云端回退，也不把原始资料
纳入应用所有权。

## 已实现

- `install-mini-gl.ps1`：创建或复用项目虚拟环境，安装锁定依赖和本地命令入口，并创建开始菜单快捷方式；`-IncludeML` 才会显式安装体积较大的本地向量依赖。
- `start-mini-gl.cmd`：启动前检查 Python 虚拟环境和运行时锁文件，失败时提供明确提示。
- `mini-gl` 控制台命令入口，以及 `product-status` 元数据诊断命令。
- 控制台展示启动器、锁文件、数据库初始化、备份数量和最近备份。
- `uninstall-preview` 与 `uninstall-mini-gl.ps1 -Preview`：在删除前列出应用自有路径。
- 卸载必须逐字输入 `UNINSTALL MINI_GL`，范围仅包括应用数据库、WAL/SHM、托管备份、虚拟环境和开始菜单快捷方式。
- 项目源码和所有注册的原始资料目录始终保留。

## 安全边界

- 安装依赖是用户显式运行脚本后才发生的联网操作；应用运行期不会下载软件或模型。
- 快捷方式只指向仓库内的只读启动入口，不注册系统服务或高权限任务。
- 产品诊断只读取运行元数据和应用自有路径，不枚举任何已注册资料目录。
- 卸载预览没有副作用；实际卸载需要交互式精确确认。

## 暂不声称完成

- 代码签名的 MSI/MSIX 安装包和自动差分更新。
- Ollama、Qwen 与 BGE 的静默安装；模型体积和供应链风险要求保持显式安装。
- Windows 登录后自动启动。当前自动同步仅在 mini_GL 运行时执行。
- 真实 QQ/微信客户端数据库接入，以及 OCR、旧版 Office 和宏文档解析。

这些项目属于分发签名、供应链发布和新数据格式准入，不应被“桌面化”名义绕过。
